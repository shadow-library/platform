## Claude-specific notes

- The `shadow-library-ecosystem` skill (in-repo at `.claude/skills/shadow-library-ecosystem/`) documents the packages' public APIs and conventions — consult it before writing any utility, helper, or component.
- Serena, Context7, Playwright, `shadow-logs-dev` and `shadow-logs-prod` MCP servers are configured in `.mcp.json`. Serena's symbolic tools are the default for code discovery and symbol edits — see "Code discovery" in `AGENTS.md` for which tool answers which question. Context7 is for public-library docs only and is never authoritative for `@shadow-library/*` packages.
- `shadow-logs-dev` and `shadow-logs-prod` read that environment's container logs, queried with **LogQL** (the old store's LogsQL is gone, and so is `_time` — bound a query with the tools' own start/end arguments and a limit). They are `gitops mcp dev` and `gitops mcp prod` from the devops repository, reading host Grafana and Loki rather than the cluster: no port-forward, and neither needs its cluster running. Retention is 24 hours for dev and seven days for prod. Each server pins `environment` to its own value plus `host` on every query, so a dev session cannot read prod and vice versa — it cannot even see that the other exists. Their handshake carries the app-directory → namespace mapping and the LogQL conventions, so read those before composing a query rather than guessing at label names.
- Both servers also read `environment="host"`, which is not a cluster: one stream, `{environment="host",app="gateway",component="requests"}`, holding one JSON line per request through the AI CLI gateway, kept 14 days. It is how this platform's AI traffic is measured — parse with `| json` and read `served_by`, `model`, `status`, `ms`, `stream`, `tools`, `fallback`, `error`, `exit_code`; always filter `| __error__=""` on a metric query, because an exchange over 512KB is stored truncated and no longer parses as JSON. Those lines also carry `prompt` and `answer` in full, including the applications' end users' content, so read them only when the question needs them and never copy them into files, commits or messages.
- `shadow-logs-prod` refuses to start without a live access grant, so it will show as failed until one is opened: `gitops access grant prod --for 1h --reason "<why>"` in the devops repository, `gitops access status` to check, `gitops access revoke prod` to close it early. The grant is checked when the server starts and not again, so opening one mid-session needs the MCP client restarted, and revoking does not end a session already running. Prod logs — identity's especially — carry real users' authentication data; never copy tokens, session IDs or email addresses into files, commits or messages.
